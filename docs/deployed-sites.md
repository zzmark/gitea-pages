# 已部署站点清单

访问控制域名的 `/sites`，或点击首页的“已部署站点”。使用现有 Gitea OAuth 登录后，页面列出当前用户有权访问的已部署仓库，包括组织仓库。权限使用浏览者自己的令牌逐个向 Gitea 核对，不借用站点部署者或组织管理员的令牌；无权限的仓库不展示，核验服务出错时显示错误而非不完整清单。

页面提供站点链接、仓库、根站点/子站点类型、Git commit 和更新时间，默认按更新时间倒序排列。搜索支持仓库名称、站点地址和完整或部分 commit。时间以 UTC 显示；页面刷新时重新读取已部署目录和仓库权限。

## 版本与历史站点

- 版本来自实际克隆工作区的 `HEAD`，不使用 Webhook 的 `after` 字段，也不在查询页面时读取分支最新版本。
- 部署完成内容校验后、原子发布前生成 UTC 时间和记录。记录与网站内容一起原子替换，因此旧站点在新版本发布前保留原版本和时间。
- 站点删除后自动从清单移除；临时 staging 目录、普通文件和符号链接不计入清单。
- 升级前的站点没有可恢复的 commit 或准确部署时间，显示“未记录”；下次成功部署后补齐。不会拿文件修改时间或当前分支版本冒充历史部署信息。
- 旧根站点兼容 `<owner>.<完整 Pages 域名>` 和 `<owner>` 两种仓库名称。只有经 Gitea 核验可访问的仓库才会展示。

## 内部记录与运维

每个站点根目录的 `.gitea-pages-deployment.json` 是系统保留文件，记录仓库 ID、仓库名称、commit 和时间，不包含 OAuth 令牌。仓库提交的同名文件或目录不会被复制。记录使用从 `TOKEN_ENCRYPTION_KEY_FILE` 派生的专用 HMAC 密钥签名，避免仓库内容伪造清单信息；Nginx 现有隐藏路径规则阻止直接访问该文件。

记录随 Pages 数据卷持久化，无需新增数据库迁移。重启后可直接读取；损坏、签名无效或与站点路径不符的记录按缺失处理。备份 Pages 数据时保留该文件，且保留对应加密密钥。轮换加密密钥后，旧签名的版本和时间显示“未记录”，下次部署重新生成。

`/sites` 响应设置 `Cache-Control: private, no-store`。如果以后放开 Nginx 对隐藏路径的访问，需要继续单独屏蔽该内部记录文件。

## 冷启动全量扫描

Gitea 管理员登录后，在 `/sites` 点击“全量扫描并补全部署”。这适用于 Deployer 新启动或丢失部署目录、但 Gitea 仓库已经存在 `gh-pages` 分支的场景。程序启动时不会自动触发扫描。

- 范围包括实例保存了 OAuth 授权的个人仓库，以及已注册组织 hook / 已保存组织授权关系的组织仓库。组织 hook 功能关闭时仅扫描个人作用域。
- 使用每个作用域各自的有效令牌分页枚举仓库；组织取所有已批准授权者可见仓库的并集并去重。触发任务的管理员令牌只用于校验管理员身份，不作为通用部署凭据。
- 再次向 Gitea 核验仓库身份，并检查 `gh-pages` 分支。缺少站点、记录缺失或版本与该分支不一致时，复用正常部署的大小限制、超时、内容安全检查和原子发布。
- 已部署版本一致则跳过；没有 `gh-pages` 分支时不删除现有站点。若记录显示同一个发布路径属于另一仓库，报告冲突并保留现有站点。历史根站点缺少记录、且两种根仓库名称都存在 `gh-pages` 时，也会报告归属冲突，避免由扫描顺序决定覆盖哪个站点。
- 扫描与 Webhook 共享部署并发限制和站点锁；取得站点锁后再读取分支及部署记录，避免与正常部署互相覆盖。

任务在后台执行，每个进程同时只允许一个全量扫描。页面每 3 秒读取进度，显示已检查、已部署、已是最新、无分支、失败数量以及最多 50 条失败详情。单个仓库失败后继续扫描其他仓库；授权过期或 Gitea 不可用会明确记录作用域失败，不当作扫描成功。

页面关闭不影响扫描；任务总时限为 6 小时。任务进度只保存在进程内存中，进程重启会中断扫描并清空进度，可以重新点击按钮续补；成功部署的站点与记录仍保留，版本匹配的站点会跳过。接口为 `POST /sites/scan`（启动，要求会话绑定的 CSRF 校验）和 `GET /sites/scan`（进度），两者均实时核验 Gitea 管理员身份。

API 对照：[个人仓库分页](https://docs.gitea.com/api/1.24/operations/user-current-list-repos/)、[组织仓库分页](https://docs.gitea.com/api/1.24/operations/org-list-repos/)、[分支版本](https://docs.gitea.com/api/1.24/operations/repo-get-branch/)。
